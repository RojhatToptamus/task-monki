# Design variations

Create distinct options so the user can compare meaningful choices.
One design is one bet.
Useful options make the differences clear.

## Set the comparison

Identify what the user wants to vary.
Use the current design system unless the user asks to explore outside it.
Use a requested count when one exists.
Otherwise, choose a small count that fits the scope.

Select two to four useful axes, such as:

- layout and information hierarchy
- density and type emphasis
- interaction model or flow structure
- visual tone and component treatment
- copy strategy or action emphasis

## Define each option first

Write one concrete sentence for each option before you build it.
State its layout, main hierarchy, and the axes that differ.
Make the set cover both a safe interpretation and a more exploratory interpretation when the brief allows it.

Options must differ in structure or product experience.
Do not present small color, radius, shadow, or spacing changes as separate directions.
Remove an option when its difference cannot be explained in one sentence.

## Present one comparison surface

Keep all options in one coherent interface or one controlled toggle system.
Use real labels and the same content across options when content is not the comparison axis.
Do not create disconnected `v1`, `v2`, and `v3` projects.

Caption each option with its main decision and tradeoff.
Offer one clear recommendation based on the user's goal.
The user makes the final choice.

Run the checks that apply to the options.
Do not turn an options request into a permanent variation system.
